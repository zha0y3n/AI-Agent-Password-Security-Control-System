# 面向 AI Agent 的密码凭据零接触与生命周期联动安全控制系统
## 3 人 × 4 周任务分工与执行计划（Python + Go 重构版）

> 团队结构：1 人 Go + 2 人 Python  
> 周期：4 周 / 28 天  
> 项目定位：AI Agent Security + Credential Usage Security + 国密密码应用  
> 分工原则：**按安全链路纵向切分，不按“密码 / 后端 / 测试”横向切分。**  
> 核心目标：**让 AI Agent 能安全使用长期业务凭据，而不是直接拥有长期业务凭据。**

# 1. 作品最终任务目标

## 1.1 一句话目标

> 即使 AI Agent 被 Prompt Injection、恶意 RAG 文档、恶意网页、工具返回值或用户输入诱导，也不能绕过密码授权边界，使用长期 Credential 产生超出授权范围的真实业务副作用。

本项目不要求：

```text
Agent 永远不会被骗
```

而是要求：

```text
Agent 可以被骗
≠
系统必须跟着被骗
```

最终安全目标：

\[
\boxed{
Use(Credential)
\Rightarrow
Verified(Capability)
}
\]

以及：

\[
\boxed{
Agent
\nRightarrow
Credential_{plaintext}
}
\]

# 3. 为什么这样分工更合理

旧分工：

```text
A = 所有密码
B = 所有后端
C = 所有测试
```

容易形成：

```text
B 等 A 的密码模块
C 等 B 的后端
```

新分工：

```text
A = Authorization Domain
B = Trusted Execution Domain
C = Security Evaluation Domain
```

三个人围绕不同安全域并行开发。

最重要的是：

> A / B 的边界不是代码接口，而是 **HTTP + JSON + 密码协议规范**。

因此：

```text
Python
  ↓
Protocol
  ↓
Go
```

而不是：

```text
Python SDK
  ↓
Go 强行调用 Python
```

# 6. 核心创新点

## 6.1 创新一：任务级 Holder-Bound Capability

传统：

```text
Agent
 ↓
Credential
```

本方案：

```text
Agent
 ↓
Holder-Bound Capability
 ↓
Credential Broker
 ↓
Credential
```

Capability 同时绑定：

```text
Subject / Agent
Agent Key
Task
Audience
Service
Resource
Operation
Request Hash
Credential ID
Credential Epoch
Expiration
Nonce
```

Capability 的本质：

```text
Credential Ownership
        ↓
Cryptographic Usage Right
```

---

## 6.2 创新二：Credential Epoch 生命周期联动

Capability 中签名绑定：

```text
credential_id
credential_epoch
```

底层 Credential：

```text
Rotate
Disable
Revoke
Compromise
Re-enable
Destroy / Recreate
```

时：

```text
epoch++
```

实现：

\[
CredentialStateChange
\Rightarrow
AuthorizationStateChange
\]

避免只依赖 Token TTL。

---

## 6.3 创新三：授权请求与真实执行请求密码绑定

不相信：

```text
Agent verbal intent
```

只相信：

\[
SM3(CanonicalRequest)
\]

要求：

\[
AuthorizedRequest
=
ExecutedRequest
\]

避免 Agent 在 Capability 签发后偷偷修改：

```text
resource
operation
path
params
body
```

---

## 6.4 创新四：原子 Credential Usage

Broker 将：

```text
Capability Validation
Holder Verification
Credential State
Credential Epoch
Nonce
Capability State
```

放入可信执行逻辑。

通过：

```text
ISSUED
 ↓
CONSUMING
 ↓
CONSUMED
```

实现：

\[
SideEffectCount(Capability)\le1
\]

抵抗并发 Replay。

---

## 6.5 创新五：Credential 使用证据闭环

每次真实调用后：

```text
Broker
 ↓
Execution Receipt
 ↓
Audit Entry
 ↓
Hash Chain
 ↓
Signed Checkpoint
```

形成：

\[
Authorization
\rightarrow
CredentialUse
\rightarrow
ActualSideEffect
\rightarrow
VerifiableEvidence
\]

# 12. Canonical Encoding

必须保证：

\[
SameSemanticObject
\Rightarrow
SameBytes
\]

统一规则：

```text
UTF-8
Object Key 字典序排序
无多余空格
整数统一十进制
时间统一 Unix Timestamp
禁止 NaN / Infinity
Null 语义明确
数组保持业务顺序
签名前必须 Canonical Encode
```

不要：

```text
Python json.dumps()
Go json.Marshal()
```

各自直接拿结果签名。

必须严格遵守 `docs/crypto-protocol.md` 中的 Canonical JSON 规范。
